How to Bulk Resize Images and Convert Them to WebP

Resize a folder or a list of image URLs to web size, convert to WebP, AVIF, PNG or JPEG, and strip EXIF and GPS data, with a desktop tool, a few lines of Python, or a pay-per-image actor.

Product photos straight from a camera are 3,000 pixels wide and 6 MB each. Screenshots are PNGs five times bigger than they need to be. Phone photos arrive sideways and carry the GPS location of wherever they were taken. Before any of that goes on a web page, it needs resizing, converting to a modern format, turning upright and stripping of metadata. Here are three ways to do it, from a desktop tool to a scheduled job.

Option 1: A desktop tool for a folder of files

If the images are on your disk, a batch converter is the quickest route:

  • IrfanView (Windows, free): File, Batch Conversion/Rename. Pick the output format, tick Advanced options for resize, and it writes a whole folder in one go.
  • XnConvert (Windows, Mac, Linux, free): drag in a folder, add Resize and Strip metadata actions, choose WebP as output.
  • ImageMagick (command line): magick mogrify -path out -resize 1200x1200> -auto-orient -strip -quality 80 -format webp *.jpg. The > after the size means never enlarge.

Option 2: A few lines of Python

Pillow handles the common formats. Install it with pip install pillow, then:

from pathlib import Path
from PIL import Image, ImageOps

out = Path("out"); out.mkdir(exist_ok=True)
for f in Path("photos").glob("*.jpg"):
    im = Image.open(f)
    im = ImageOps.exif_transpose(im)              # turn phone photos upright
    im.thumbnail((1200, 1200))                    # fit inside the box, never enlarge
    im = im.convert("RGB")
    im.save(out / f"{f.stem}.webp", "WEBP", quality=80)   # save() writes no EXIF

For square thumbnails, use ImageOps.fit(im, (400, 400)) instead of thumbnail, which crops the edges to fill the box.

If the images are URLs rather than files, add a download step with requests, check the site's robots.txt, pause between requests to the same host, and cap the download size. Pillow needs the pillow-avif-plugin package for AVIF, and it does not read HEIC without another plugin.

What to decide before you start

  • Format. WebP for web pages: small, and every current browser shows it. AVIF is smaller still but slower to make. JPEG when an older tool needs it. PNG when you need lossless output or crisp edges on screenshots.
  • Fit. Keep the shape and fit inside a box (most photos), crop to fill (thumbnails in a grid), pad to fill (logos on a fixed card), or stretch (almost never).
  • Never enlarge. Upscaling only adds blur and bytes.
  • Metadata. Strip it. EXIF carries the camera model, the date and, for phone photos, the GPS location.
  • Colour profile. Convert to sRGB before stripping, or colours shift in the browser.

FAQ

Can I get every image at exactly the same size?

Set both width and height and use fit: "cover" (crops) or fit: "contain" (pads). A source smaller than the box is not enlarged, so with cover it comes back smaller than the box.

Does WebP lose quality?

At quality 80 the difference from the source is hard to see and the file is usually 60 to 90 percent smaller than a JPEG of the same size. Use PNG when you need lossless.

Why is a small JPEG bigger after converting to PNG?

PNG is lossless and poor at photos. Use it for screenshots, drawings and images with transparency, and WebP or JPEG for photos.
