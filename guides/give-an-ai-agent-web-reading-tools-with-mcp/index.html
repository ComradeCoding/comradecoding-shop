How to Give an AI Agent Web Reading Tools with MCP

Let Claude, Cursor or your own agent read web pages as Markdown, PDFs as text, feed items and sitemap URLs through one MCP server, self-hosted or pay per call.

An agent that can only see what you paste into the chat is stuck the moment it needs a docs page, a PDF report or this week's blog posts. The Model Context Protocol (MCP) is the common way to hand an agent tools: a server lists its tools, the agent calls them with JSON arguments and gets JSON back. Most coding assistants and agent frameworks speak it now.

The four tools an agent asks for most often are: read a web page as clean text, read a PDF, read a feed, and list a site's pages. Here is how to provide them yourself, and the hosted route when you would rather not run a server.

Option 1: Write a small MCP server

The official Python SDK makes a tool out of a decorated function. Install it with pip install mcp trafilatura pypdf, then:

from mcp.server.fastmcp import FastMCP
import trafilatura, io, urllib.request
from pypdf import PdfReader

mcp = FastMCP("web-reader")

@mcp.tool()
def url_to_markdown(url: str) -> str:
    """Main text of a public web page as Markdown."""
    html = trafilatura.fetch_url(url)
    return trafilatura.extract(html, output_format="markdown") or ""

@mcp.tool()
def pdf_to_text(url: str, max_pages: int = 50) -> str:
    """Plain text of a PDF at a URL."""
    data = urllib.request.urlopen(url, timeout=60).read()
    reader = PdfReader(io.BytesIO(data))
    return "\n\n".join(p.extract_text() or "" for p in reader.pages[:max_pages])

mcp.run()

Point your client at the script as a stdio server and the two tools appear. Add feedparser for feeds and a sitemap walker for URL lists and you have the full set.

What the small server does not do

Before you let an agent loose on the open web with it, you will want to add:

  • robots.txt checks and a pause between requests to the same host, so the agent does not get your IP blocked.
  • Private address blocking. An agent fed a link to localhost, 169.254.169.254 or 10.0.0.1 would otherwise read your own network.
  • Size and time caps per call, so one 200 MB PDF or a page with a million nested tags does not hang the server.
  • Encoding and content type handling, including PDFs served as application/octet-stream.
  • Clear error messages the agent can act on (Disallowed by robots.txt, This URL is a PDF; use pdf_to_text).
  • Hosting somewhere reachable when the agent runs in the cloud, not only on your laptop.

Option 2: Connect to a hosted server

Web to Text MCP Server, an Apify actor, provides the same four tools over Streamable HTTP, with the checks above built in:

  • url_to_markdown: main text of a page as Markdown, with title, description, language and word_count. Arguments: url, max_chars, include_links.
  • pdf_to_text: text of a PDF up to 20 MB, with page_count, title, author and dates. Arguments: url, max_pages, max_chars.
  • feed_items: the newest items of an RSS, Atom or JSON feed, each with its text as Markdown. Arguments: url, max_items, include_content, max_chars_per_item.
  • sitemap_urls: a site's page URLs from its sitemaps, up to 5,000 per call. Arguments: url, max_urls, max_sitemaps, url_contains.

Add it to a client config with your Apify API token as a bearer header:

      "url": "https://comradecoding--web-to-text-mcp.apify.actor/mcp",
      "headers": { "Authorization": "Bearer YOUR_APIFY_TOKEN" }

  }
}

Clients that only run local stdio servers can bridge with npx mcp-remote https://comradecoding--web-to-text-mcp.apify.actor/mcp --header "Authorization: Bearer YOUR_APIFY_TOKEN". If your agent already uses Apify's own MCP server, the tools also show up through https://mcp.apify.com?tools=comradecoding/web-to-text-mcp.

To call a tool from your own Python code without an MCP client, send the JSON-RPC request directly. The server is stateless and answers with JSON:

import requests

r = requests.post(
    "https://comradecoding--web-to-text-mcp.apify.actor/mcp",
    headers={"Authorization": "Bearer YOUR_APIFY_TOKEN",
             "Accept": "application/json, text/event-stream"},
    json={"jsonrpc": "2.0", "id": 1, "method": "tools/call",
          "params": {"name": "url_to_markdown",
                     "arguments": {"url": "https://developer.mozilla.org/en-US/docs/Web/HTTP/Status/404"}}},
)
result = r.json()["result"]
print(result["structuredContent"]["title"])
print(result["structuredContent"]["markdown"][:500])

Pricing is per successful call: $0.005 for url_to_markdown and pdf_to_text, $0.002 for feed_items and sitemap_urls. 1,000 pages is about $5; 1,000 feed checks about $2. Failed calls (bad arguments, robots.txt refusals, HTTP errors, size or time limits) return a plain error and are free, as are initialize, tools/list and ping.

Its limits: public pages only, no logins, cookies or JavaScript rendering. No OCR, so a scanned PDF returns has_text: false. Pages up to 5 MB, PDFs up to 20 MB, feeds up to 10 MB. feed_items returns what the feed carries; call url_to_markdown on an item's url for the full article. Sites asking for a crawl delay over 10 seconds are skipped.

FAQ

Which clients can use it?

Any MCP client that supports Streamable HTTP with custom headers, and stdio-only clients through mcp-remote. The config block above is the shape most clients use; check your client's docs for the file location.

How is this different from the batch actors?

The MCP server answers one call at a time, which is what an agent needs mid-conversation. For hundreds or thousands of URLs in one go, use the batch actors: URL to Markdown, PDF to Text, RSS to JSON and Sitemap URL Extractor.
