How to Convert RSS and Atom Feeds to Markdown for an AI Agent

Turn feed items into one Markdown document per article, with the full text when the feed only carries a teaser, using a few lines of Python or a scheduled run that returns only new items.

A language model reads Markdown well and HTML badly. If you want an agent to summarise this morning's blog posts, watch release notes, or build a news digest, the cleanest input is one Markdown document per article: title, date, link, then the body with headings and lists kept and the site chrome gone. Feeds get you most of the way, but they are XML, and many of them only carry a short summary rather than the article.

Here is how to get there with a short script, and when a hosted actor is the easier route.

Step 1: Read the feed and convert the summary

The free feedparser library reads RSS, Atom and JSON Feed into one structure, and markdownify turns the HTML in each item into Markdown. Install them with pip install feedparser markdownify, then:

import feedparser
from markdownify import markdownify

feed = feedparser.parse("https://blog.rust-lang.org/feed.xml")
for e in feed.entries[:10]:
    body = e.get("content", [{}])[0].get("value") or e.get("summary", "")
    doc = f"# {e.get('title')}\n\n- Link: {e.get('link')}\n\n---\n\n{markdownify(body)}"
    print(doc[:300])

For feeds that include the whole post (many developer blogs do), this is already enough.

Step 2: Fetch the page when the feed is only a teaser

News sites and most company blogs put one or two sentences in the feed. For those, open the item's link and extract the main text. trafilatura does the extraction and can write Markdown directly:

import trafilatura

html = trafilatura.fetch_url(e["link"])
text = trafilatura.extract(html, output_format="markdown", include_links=True)

Decide per item: if the feed text is short, say under 150 words, fetch the page; otherwise keep the feed text and save a request.

Step 3: Things that go wrong at scale

  • robots.txt and crawl delays. Check them before fetching pages, and pause between requests to the same site.
  • Encoding. Some servers send the wrong charset header, and accented letters come out mangled.
  • Dates. Feeds mix ISO 8601, RFC 822 and plain mistakes. Normalise to UTC before sorting.
  • Duplicates. The same post appears under several URLs with utm_ parameters, or the feed repeats items between runs. Keep a store of keys you have already handed to the model.
  • Pages built with JavaScript. They return little text to any tool that reads the server HTML. Keep the feed text for those.
  • Relative links and images. Make them absolute, or the model cannot follow them.

Each of these is a few lines, but together they are a small project to maintain.

The no-code or scheduled route

Feed to Markdown for AI Agents, an Apify actor, does all of the above for a list of feed URLs. For each item it returns title, url, author, published_at and markdown: one document that starts with the title, date and link, then the body with absolute links. content_source says whether the text came from the feed or the page, and page_error says why a page could not be used.

The options that matter for an agent pipeline:

  • contentMode: auto (default) uses the feed text when it has 150 words or more and opens the page otherwise; page always opens the page; feed never does.
  • publishedAfter: skip items older than a date or an age such as 24 hours or 7 days.
  • seenItemsStore: name a store, and every scheduled run returns only items earlier runs have not returned.
  • includeImages: turn off for shorter, text-only output.
  • maxItems and maxItemsPerFeed: cap the run.

Run it from Python with the Apify client (pip install apify-client):

FAQ

How is this different from converting the feed to JSON?

RSS and Atom to JSON gives you many structured fields per item with a plain text summary, for databases and spreadsheets. This gives you one Markdown document per item, with the article body, for a model.

Can I get the archive of older posts?

Not from the feed. Start polling now with seenItemsStore and keep what you collect, or list the site's older pages from its sitemap and convert them with URL to Markdown.

Does it work for podcasts?

The feed items convert, but the audio is not transcribed. You get the show notes as Markdown.
